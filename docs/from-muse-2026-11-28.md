## 2. 図種ゲートの設計（形の決まりはむぎ、実装はお願いしたい）

非平面の図（立面・断面・天井伏・電気設備）では、形の辞書による器具・家具の「確定」を出さない仕組みの設計。

- **動機**：dxf_10 の 08（タイトル「LIGHTING_PLAN」の電気設備図）で、照明記号 Ø360＋十字の4件が全部「小便器・検出（0.947）」になった。
  360 は小便器の寸法帯にすっぽり入り、形だけでは分けられない。この図面の面・面積は正解と一致しているので、落とすのは器具の形判定だけ。
  z3/09 の天井伏図でも、A-FIXT の 360×360 正方形＋十字6組が同じ帯に入る。
- **単位はシート領域ごと**（ファイル全体ではない）。帰属は中心点がどの `analysis.sheets` の box に入るか。どの領域にも入らなければ止めない。
- **種類の決め方**（優先順）：(1) 図名・表題の文字を文の辞書の sheet エントリで照合（英語は単語境界）。
  ELEVATION・SECTION・RCP・REFLECTED CEILING・立面図・断面図・天井伏図・展開図に加えて、
  **電気系の語（LIGHTING・ELECTRICAL・照明・電気設備）を sheet エントリに足す必要がある**（今は無い）。
  (2) シート内の文字の走査。(3) レイヤーの手がかり：電気・天井系レイヤーの割合が3割以上かつ10要素以上なら非平面寄り
  （根拠の実測：dxf_10/08 は 36/49 = 73%、z3/09 は 78/104 = 75%）。(4) 形の手がかりは補助のみ。どれにも当たらなければ止めない。
- **DETAIL の扱いが要点**：z3/07「WET AREA DETAIL」は詳細図だが中身は本物の衛生器具（第1弾の簡略記号パターンの元）。
  なので **DETAIL 単独では止めず**、DETAIL＋階段・構造系の語がある時だけ止める。水回りの語があれば平面側に倒す。
- **止める物**：その領域内での `classifyBox`／`classifyFixtureShape`（形証拠の分岐込み）／`classifyCluster`／fixrescue の確定と、
  エンジンの器具リストの計数。確定の代わりに「要確認（非平面図のため形判定を保留）」止まり。
  **例外：ユーザ辞書は止めない**（利用者が教えた物は明示的な意思のため）。
- **止めない物**：文の辞書の照合すべて、部屋・区画・面積の読み、寸法・縮尺の照合、ドア検出、アプリの電気まわりの機能。
- **期待される効果**：実図面5枚はすべて平面なので**変化ゼロ**。dxf_10 再スコアで 08 の誤確定4件が消える（(a) の誤り 21件→17件の見込み）。
  z3 では 09 RCP の記号が器具に化けなくなり、**07 WET AREA DETAIL の器具4件は今までどおり拾える**ことが回帰確認の必須条件。
- **置き場所の案**：`viewKind` は reader2 の解析段でシートごとに持たせる（材料は `sheetTitles` のタイトルと textdict の sheet エントリに既にある）。
  ゲートは判定関数の外側、project.js が判定結果を集める段で「確定→要確認」に一段落とす形にすると、平面図側の挙動が変わらない。
