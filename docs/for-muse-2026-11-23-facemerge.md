# むぎへ：区画が分かれすぎる件、くらちゃん側で入れたよ（2026-11-23）

かつから「家具を図面から一旦外して、壁の線でどこまでが区画か分かるようにする予定。くらちゃん出来そうならやってね、直せたらむぎにメモだけ」と頼まれたので、kaku_generation に入れた。むぎの方で同じ所を作り始めていたら、ここを見て合わせてほしい。

## 何をしたか

- 新しい部品 `js/facemerge.js`（`mergeSplitFaces`・`splitMerged`）。読み取りの部品（エンジン）は触っていない
- 図面を読み込む時、もともと作っている「試しの区画」（`drawing.v2` の元。1本線・6m未満の線のかたまり＝家具を外して、壁の線だけで探した区画）を使う
- **試しの区画1つの中に、今の区画が2つ以上すっぽり入る所だけ**、今の区画をその1つに置き換える。それ以外の区画は今の読み取りの数字のまま（試しで消える部屋も今のまま残る）
- まとめない所（壁を家具と見間違えた疑い）：
  - 中の区画に違う部屋名が2つ以上
  - 中の区画の2つ以上に便器・小便器（トイレのブース）
  - 中の間仕切りのドア（幅55cm以上。ちょうつがいが中ほど、または扉の開く所が中ほどで、中の区画2つのふちの間にある）
  - 試しの区画の形が、中に入らないほかの区画（1㎡以上。階段・EV など）にかぶる／輪の形
  - 中の区画の広さの合計が、試しの区画の半分未満・1.05倍超
- まとめた区画は `plan.split[新しい i] = { faces: 元の区画, open: 元の開口 }` に覚える。区画の `merged` に元の区画の番号
- 画面：まとめた区画を選ぶと「机・棚などの線を外してまとめた区画」の札と「細かい区画に分ける」ボタン（部屋に入っている時は先に部屋から外す）。分けると元の細かい区画に戻る（元に戻すの境目）
- 開口：まとめた区画は試しの開口を使う（扉の無い開口が周りの3割以上ならドアだけ。試しの時と同じ決まり）

## 確かめたこと

- 正解付き25枚：部屋が合う数は前と同じ（区画の数は11枚で減る。全部絵で見た：机・椅子・畳の線・浴室の浴槽の線で割れていた所がまとまる）
- 現場トイレ（基準）：区画・器具・開口とも前と全部同じ（まとまる所なし）
- 器具の数・種類：30枚とも前と同じ
- 実図面：自動車学校の事務所が机・椅子の下ごと1区画に（かつの画面の所）
- 気になる所：工場の図面で、階段の上り口まわりと隣の広い所がまとまる所がある（試しの区画の弱い所がそのまま出る）。「細かい区画に分ける」で戻せる
- **前に読み込んだ図面は読み直さないと変わらない**

## むぎにお願い

- むぎ側でゾーン分け（`zones.js`）や補足区画（`polygonize.js`）を区画の番号で持っている所は、まとめた区画は新しい番号（`i`）になる。読み込みの順番はまとめた後に解析・ゾーン・補足区画を作るので食い違わないはず。「分ける」をした後はゾーンが元の番号を指さなくなる（ゾーンは候補なので、そのままにしている）
- 階段まわりがまとまる件をもっと減らす決まりがあれば、考えてほしい（直すのはくらちゃん）
