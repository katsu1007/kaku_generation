# くらちゃん（Claude）へ：器具の形判定とタンク帯の確定（sw.49／50 の引き継ぎ）（2026-11-22・むぎ＝Muse）

前のメモ §7 で約束した別メモ。muse_kaku の sw.49（器具の形判定の表示）と sw.50（タンク帯での便器確定）の設計と実測。そちら（kaku_generation）に取り込む時の材料に。お客さんの図面そのもの・正解の数は書かない方針は同じ。

## 1. 課題

器具は外形の箱しか持っていないため、符の表示は寸法だけの判定になり、接戦（スコア 0.90 以上でも 2位との差が 0.05 未満）で「類似」に倒れる。衛生器具の多い図面では、表示が全部「類似」になることがあった。寸法だけの確定は正確さが低い（実測 15.9%）ので、確定には形の証拠が要る、というのが出発点。

## 2. sw.49：器具本体の線から特徴を取る（js/fixshape.js）

- 線のプールは「全線」（グループの ON／OFF を問わない）。器具のレイヤーが表示用の線プールに残らない図面があるため。ハッチングは除く、上限 15万本。
- 箱＋100mm の範囲に中点が入る線を集め、端点の近さ（45mm）でかたまりに分ける。
- 受け入れは2段。(1) かたまりの輪郭が箱の幅・高さの 85% 以上を覆い、はみ出し 60mm 以内。(2) はみ出し 30mm 以内 かつ 箱内の線の 60% 以上を持ち、次点が 40% 以下。同程度の大きさの物が2つ並ぶ場合は、特徴なしに倒す（無理に決めない）。
- 特徴は家具判定と同じ定義（短い線・長い線の割合、曲線の割合、閉じた形、仕切りの数）に、innerClosed を追加：輪郭から 45mm 以上内側にある、80mm 以上の閉じた輪。ボウルの楕円は真、小便器の内側の開いた曲線は偽、小さいセンサー円は寸法の下限で除く。
- 試して捨てた方法：線を「端点が箱内」でも集める拡張は、机の検出が落ちた（6件→1件）ので不採用。測定した方法が正。
- 表示で形の確定を出す範囲は、実測で全件正解だった机・椅子（オフィス什器）だけに制限した。制限なしでは 12件中 5件の誤り（SK→洗面器、アームチェア→キッチン 0.992）。衛生器具は形だけでは確定できない（§4）。

## 3. sw.50：タンク帯を特徴に足す

- tankBand は、種類の直し（typefix）にある hasTankBand の測り方を、受け入れたかたまり自身の線だけに適用する。全線プールで測ると小便器・洗面器まで「帯あり」に飽和する（前メモ §5）。
- ルール：tankBand＝真 かつ innerClosed＝真 の時だけ、流し・SK を候補から外して辞書判定をやり直し、洋式大便器が通常の確定条件（スコア 0.90 以上・2位との差 0.05 以上・寸法の拒否なし）を満たせば「検出」にする。
- 結果：新規の検出は便器 18件で全件正解、誤り 0。辞書の物差しは 75.9% → 77.3%。種類の直しの入出力は完全不変。テストは全件通過。
- 入れなかった経路：「帯なし → 小便器」（小便器は帯で分けられない。前メモ §5）、「洗面器を候補から外す案」（誤り 19件で不採用）。

## 4. 実測で分かった限界

- 便器の形は、SK ダブルボウルの実測パターンとほぼ一致する（0.978 対 0.931）。形の1位は概ね正しい側でも、差が 0.002〜0.049 で確定の物差し（差 0.05）に届かない。衛生器具は「形＋文脈証拠（タンク帯）」の組でないと確定できない、が結論。
- ブースに囲まれた個室の便器は、特徴の取り出し自体が成立しないことがある（対象外のまま）。そちらの救済（jbowl 等）が拾えている所とは手段が違う。

## 5. 取り込む時の注意

- 特徴は数値だけを器具に付ける（線そのものは保存しない）。旧案件には特徴が無いので、表示は「読み直す」まで従来通りになる。
- 辞書の判定関数には候補の除外オプション（opts.exclude）を足しただけ。既存の呼び出しは引数なしで、結果は変わらない。
- 検証はこちらと同じ物差しで：複数図面の前後比較で悪化ゼロ、新規の検出は全件正解、を出荷条件にしている。
