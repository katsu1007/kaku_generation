### 保存する所（ぶつからないように）

- `company.estNote`（文字）・`company.estNoteOff`（true なら載せない）・`company.logo`（data URL）
- どれも**会社の設定**なので、保存先フォルダの `_KAKU_会社の設定.kaku.json` にも入る（ロゴの分だけファイルが大きくなる。縮めてあるので数十KB程度）
- `settings.lastBackup` は今まで通り端末だけ（`LOCAL_ONLY`）

### 気を付けた所

- 印刷用のロゴの class は **`colog`**。最初 `logo` にしたら、アプリの `.logo`（左上の橙の四角）の CSS が当たって、ロゴが小さい橙の四角に化けた。もしそちらで書類の CSS を触る時は `.logo` を使わないでほしい
- 書類の CSS は、アプリ（IPA）の PDF では `css/app.css` の `.doc` で始まる行だけを抜き出して使う（`printDoc`）。足した行も `.doc .co .colog`・`.doc .disc` で始めてある

## 5. 追記：むぎ由来のコードが「置いてあるだけ」でなく実際に動いているか（実行の道筋で確かめた）

別の担当（ChatGPT）から「コードがあるのと、アプリで使われているのは別。main.js は解析の部品を直接読んでいないし、README には図面解析は旧画面と書いてある」と指摘があったので、実行の道筋を追った。

- 読み込みの道筋：`main.js` → `project.js`（`import` で fixrescue・fixshape・symdict・typefix・furndetect・polygonize・zones・roomjudge を読む）→ ②部屋で図面を選ぶ（`#dwgFile`）→ 前のKAKUの部品で読み取り（`legacy.js` の iframe）→ その結果に `project.js` が救済・形の特徴・家具・補足区画・ゾーンを足す
- ブラウザの計測（CDP の Profiler。関数ごとに呼ばれた回数）で、正解付きの3枚（F1_public_restroom・hotel_twin・school_wc_1f2f）を新しい画面から読んだ時の回数：
  - `createShapeIndex` 2・`featuresFor` 16〜52・`classifyFixtureShape` 4〜12・`classifyFixtureDisplay`（器具の数だけ）・`correctFixtureTypes` 1・`classifySymbol`・`detectFurniture`・`supplementFaces`・`computeZones`・`judgeRooms` 各1 → **sw.49／50 の形の判定・タンク帯は実際に動いている**（F1 で器具13個のうち形の特徴あり10・タンク帯あり8、school_wc で 12・10）
  - `rescueFixtures`・`KF_jbowl`・`KF_tubs` は 0回：救済は「壁も扉も器具も1つのレイヤー」の図面だけで動く決まり（`legacy.js` の材料作りで、扉の円弧と長い線の多いレイヤーが候補に無ければ材料を渡さない）。この3枚はレイヤーが分かれているので動かないのが正しい。三井屋（1レイヤー）は手元に無いので今回は回せていない（前の記録では、新しい画面で三井屋 34/34）
- README の「図面の読み込み・照明・3D は前のKAKUで使える」は古い書き方だったので直した
