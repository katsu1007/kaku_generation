## 1. 家具クラスタの線の出し方（依頼1）

### 今のままでは出せない — 必要な変更は1か所

`js/furndetect.js` はクラスタの構成線を内部の `members`（Set）に持つが、返す直前に `delete c.members` で消している。返る物は `{b, short, long, arcShare, closed, dividers, n}` だけ。**今のアプリは構成線を出せない。**

必要な変更（設計のみ。むぎ側では未実装）：`furndetect.js` で `members` を消さずに残すか、`lines: [構成線の plan.segs 上の index]` を返すようにする。ただし保存案件（`drawing.furn`）に持たせると保存データが膨らむ（検出クラスタだけで 25,289 本）ので、**保存には載せず、読み込み時にメモリ上だけで作る関数**にするのが筋。`js/polygonize.js` の `segsWithoutClusters`（muse_kaku sw.54）がすでに「外形＋線本数で成分を照合する」再導出をアプリ内でやっているので、同じ照合を流用する手もある。

### 提案するペイロード

```json
{
  "drawing": "sample2_office_1-5.jww",
  "units": "m",
  "segSpace": "plan.segs (engine, 1mm丸め)",
  "clusters": [
    {"id": "sample2-U12", "bbox": [x0, y0, x1, y1], "category": "机・デスク",
     "verdict": "hit", "score": 0.97, "shortMm": 700, "longMm": 1400,
     "lines": [[x1, y1, x2, y2], "..."], "n": 12}
  ]
}
```

- `lines` は構成線そのものの端点座標（m・1mm丸め）。エンジンの線に安定した番号が無いため、座標で渡す。くらちゃん側は端点 5cm 以内で照合するか、線の重なり（共線・9割以上）で照合すること。`n`（線本数）と `bbox` を併記するので、照合が怪しい時は `segsWithoutClusters` と同じ「外形＋線本数」での照合に切り替えられる。
- 対象は **verdict "hit" の家具カテゴリのみ**（机・椅子・ソファ・ベッド・ロッカー・収納。器具類＝小便器・洋式大便器・洗面器・流し・SK・キッチンは含めない）。"near"（類似・114件）は**別枠**にする。
- 椅子は線の量が圧倒的なので、くらちゃん側で「椅子の線まで抜くか」は別に選べるよう、カテゴリは必ず付けること。

### 提案する使い方（くらちゃん側の区画探し）

1. まず **C（ガード付き）** で入れる：検出クラスタの線を抜くが、長い直線または今の区画のふちと重なる線は残す。最大面が動かないことが5図面で確認済み。
2. 次に **D（机・棚・ロッカー・ベッドだけ）** を試す：B とほぼ同じだけ 0.25㎡以上の断片が減り、抜く線は 1/27。最大面の動きも小さい。
3. B（全部抜く）は、大天の117.4㎡の統合が正解で正しいと answer_eval で確認できてから。確認なしに入れないこと。
4. "near" の机は、まず hit だけで回してから、別スイッチで試す。なお大天の机・デスク52件のうち実机は hit 12台だけで、**near 40件は 600×600mm の楕円の誤ラベル**（§4 参照）なので、near を入れる時はこの誤ラベルを先に直すこと。

### 確かめ方

- 5枚＋正解付き25枚で answer_eval：1区画で合う部屋の数（今42）が増えること。便所ブース・階段・EV前・上部吹抜が壊れないこと（今合っている所が減らないこと）。
- 大天の117.4㎡統合の正誤は answer_eval の部屋単位で見る（統合された先が正解の1部屋なら正しい）。

## 2. 棚の列・カウンターと間仕切りの見分け（依頼2）

### ルール（2行版）

**間仕切りとして残すのは「間隔5〜35cm・長さ1.5m以上・両端が短辺で閉じていない・両端が外の線に触れ・両端が面の境界に乗り・中点が面の境界から間隔/2の位置にある」二重線だけ。棚・カウンターとして区画探索から外すのは、辞書で棚・机と判定されたクラスタの線か、短辺で両端が閉じた箱（間隔30〜80cm）で、かつその中点が閉じた箱のクラスタ bbox 内にあるものだけ。** それ以外は未決定（＝現状どおり残す）。

### 測った数（実測と提案の区別つき）

- 棚の深さは **すべて450mm**（大天 18件すべて・江南 5件。**実測**）。机の深さは最小 **487mm**（**実測**）。**間隔上限35cmは、この2つの最小深さの間に置いた提案値**。辞書が拾い漏らしたカウンター状の箱を幾何で2件発見：日本モウルド 528×5400mm の閉じた箱、江南 480×4212mm・3辺（壁側の辺が無い＝壁を第4辺とする描き方）。
- 棚は閉じた箱（4辺とも実線）であることが多い：大天 **17/18**、江南 **5/5**（**実測**）。棚は壁付けが基本：大天の棚の長辺 36辺のうち **35辺が30cm以内に平行線を持つ**（**実測**）。机はフリースタンディングが多い（大天の机 104辺のうち77辺が30cm超）。
- **閉端テストが一番効く**：薄い二重線（5〜35cm）1,809組のうち両端閉 405組・片端閉 269組・両端開 1,135組（**実測**）。トイレだけの図面（ジェイテクト）では薄い二重線の両端閉は **0/26**。ただし例外が2つ：(1) 長い閉じた箱＝壁の輪郭（薄い＋両端閉＋長さ3m以上は計65組。最大は大天の外壁ペア 間隔6cm・長さ40.4m×5コピー）。**長さ3m以上は家具扱いしないガードが要る**。(2) 片端閉 269組は片側だけ壁に付いた棚などで、間仕切り判定には使えない。
- 端の外部接触・面境界乗りは単独では弱いテスト（端が何かに触れるのは当たり前）。ただし「ゾーンに影響する線」の絞り込みとしては使える。

### 複合条件の漏斗（KEEP＝間仕切りとして残す・実測）

薄い（5〜35cm）＋両端開＋長さ1.5m以上＋両端外部接触＋両端面境界乗り＋面の境界性（中点〜face辺が間隔/2±4cm）で、1,135組 → **193組**（ジェイテクト14・大天90・江南27・日本モウルド53・三井屋9）。一番削るのは「両端面境界乗り」（大天で168組、江南で133組、三井屋で85組を落とす）。落としたものの多くは実在の間仕切りのはずだが、**面の境界に乗らない線は現行の face ベースのゾーン計算では部屋を分け得ない**ため、ゾーン目的では外してよい（ゾーンエンジンが線ベースに変わる場合はこの前提は崩れる）。

### 複合候補の誤認率（辞書照合による下限・実測）

193組のうち辞書の家具と確定するものは **7組（3.6%）**：大天のソファの縁 1組、江南の机3台の内側線 6組。**7組すべて中点が家具の bbox 内**にある＝残しても家具自身の面が細切れになるだけで、部屋は分断しない（被害は限定）。ただし辞書が拾っていない家具はこの照合では見えないため、**真の誤認率は 3.6% が下限**。紫線の正解との直接照合はできていない（dump に紫線が含まれない）ため、KEEP の真の適合率・再現率は未測定。

### 大天の机列の危険ケース（実測）

- **机列の長辺ペアは間隔が合わない**：机の深さは最小487mm、机列は1390〜1800mm。間隔上限35cmの二重線ルールは机の長辺をそもそも拾わない。机列の長辺ペア（間隔40〜70cm・両端閉）は大天で99組あり、そのうち両端外部接触＋両端面境界乗りを満たすものは **72組**（14/コピー、うち長さ3m以上が29組）。**間隔帯を70cmまで広げたら、この72組が間仕切りとして残り、机列が区画を分けたままになる。間隔35cmの上限がオフィスを守っている。**
- 机列の端は壁に届いていない：実机12台の長辺端4点（計48点）のうち、5cm以内に何かの線に触れるのは **18点**。4点すべて触れる机は **0台**。4.08mの机列2台は最も近い端でも **10.5cm** 離れている。机列の線だけでは部屋は分断されない（ただし机＋椅子＋棚が鎖状につながって壁から壁へ届くか＝チェーンは**未測定**）。

### 棚候補の罠 — 混合ペア（外してはならない・実測）

閉両端＋間隔30〜80cm＋長さ1〜3.5mの「棚候補」ペアは大天127組・江南50組・日本モウルド19組・三井屋1組。ところが中点がどれかのクラスタ bbox 内にあるのは大天で **18/127組**、江南で 25/50組、日本モウルドで 2/19組に過ぎない。**大天の109組は無所属**。実例：間隔41.8cmのペアは「1.18mの繰返しユニットの縁＋それに沿う4mの長い線」という**混合ペア**（家具の線1本＋壁・長線1本）。2本の線が別の物の線であるペアを「棚」として外すと、壁の線まで消して部屋を併合してしまう。→ **幾何の棚候補は、辞書の箱（または閉じた箱のクラスタ bbox）と結びついたものだけ外す。無所属の棚候補は未決定（残す）とする。**

### 提案ルール（実装できる形）

入力：二重線ペア（軸平行・各線1m以上・間隔0.03〜0.80m・重なり0.8m以上）＋各ペアの特徴量（間隔・長さ・閉端・両端外部接触・両端面境界乗り・面の境界性・中点が入るクラスタ bbox）＋クラスタの特徴量（verdict／category／score、短辺・長辺、4辺カバー率、dividers、arcShare）。

1. **KEEP（間仕切りとして残す）**：間隔 **5〜35cm** かつ長さ **1.5m以上** かつ**両端開**かつ**両端外部接触**かつ**両端面境界乗り**かつ**面の境界性**をすべて満たす。→ 測った限り193組が該当。しきい値の出所：間隔5〜35cmは実測（壁厚3〜5cm・ブース15〜20cm・机内側線6〜20cmを含む帯。35cmは**提案値**）。長さ1.5mは**提案値**（1.0mに下げると薄い・両端開が419組増える。ブース間仕切りは1.5〜2.5mが多いが、1.0〜1.5mの短い間仕切りも実在するはずで、どちらが正しいかは正解付き図面での検証が必要）。追加の安全弁（**提案**）：ペアの中点が辞書の家具クラスタ（hit/near・家具ファミリ）の bbox 内にある場合は、KEEPにしない（未決定へ）。測った誤認7組は全てこれで除ける。代償（壁が家具 bbox を横切る場合の見逃し）は未測定。
2. **EXCLUDE（家具として外す）**：次のどちらか。
   - (a) **辞書ルート**：ペアの両方の線が同一の hit/near クラスタ（棚・机・カウンター系カテゴリ）の構成線である、またはペアの中点がそのクラスタの bbox 内にある。
   - (b) **幾何ルート**：ペアが**両端閉**かつ間隔 **30〜80cm** かつ長さ **1.0〜7.0m** かつ中点が「3辺以上カバー率0.7以上の閉じた箱クラスタ」の bbox 内にある。長さ上限7.0mは机列の実測最大6.91mからの**提案値**。
   - (b)の「bbox内」条件は必須。無所属の棚候補（大天で109組）は混合ペアを含むため外してはならない。
3. **UNDECIDED（現状どおり残す）**：それ以外すべて。特に次は残すこと。
   - 薄い＋両端閉＋長さ3m以上（＝壁の輪郭。外壁40.4mを含む。計65組）。
   - 薄い＋片端閉、薄い＋長さ1.5m未満、面テストを満たさない薄いペア。
   - 間隔30〜80cmで(b)の bbox 条件を満たさないペア（混合ペア）。
   - 辞書で unknown のクラスタの線（壁の1本線クラスタ等を含む。外さない）。

### 実装上の注意

- ペア抽出は **S（ゼロ長セグ除去済み）・重複除去済みのセグ** で行うこと。
- 1m以上のセグはほぼ軸平行（98.6〜100%）だが、斜め壁のある図面では斜めペアの扱いが未測定。軸平行以外は未決定とすること。
- 壁の線はドア・開口で細切れになるため、同一線上の断片を統合しないと長い間仕切りが複数組に割れる（現行の統合は座標±3cm・重なり接触のみ）。**断片統合（ギャップ0.3m以内の同一線上セグのマージ）は提案**であり、未測定。
- **階段ガードが別途要る**：階段の踏面（ピッチ248〜250mm・並行線）は本測定では数えていない。間隔25cm・長さ＝階段幅で、階段幅が1.5m以上あると KEEP 条件に入り得る。from-muse-2026-11-23b の階段ガード（踏面の並行等間隔パターンの除外）を先に適用すること。長さ1.5mのしきい値が階段を守っているかどうかは未検証。

## 3. 通り芯・天井線の手がかり（依頼3）

### 前提の訂正 — 通り芯は部屋の中を走らない

通り芯は図面の外側（壁から 2.2m 以上離れた余白）に描かれている。大天では下辺の外側（壁から 2.16m）、江南では下辺の外側（壁から 2.2m）。したがって「部屋の中を壁から壁へまっすぐ通る長い1本線＝通り芯候補」という出発点自体が誤りで、**区画の過分割の原因として疑われた通り芯は、この5図面では区画を割っていない**（面と交わらないため）。

### 長線センサス（≥5m の内部の長い線 133本の正体・実測）

- 内部の長い線のうち通り芯は **6本だけ（江南のみ・4.5%）**。「長い室内線」を通り芯の信号にすると母集団の 95% が誤り。

### 天井線：存在しない（実測の結論）

### 提案するルール（バブル優先・幾何のみ）

入力：`segs`・`texts`。面は使わない。出力：通り芯（位置・方向・バブル＋ラベル・通り間隔）。

1. **円ループ検出**：長さ <8cm の線分を端点 5cm 以内で連結し、直径 0.30–0.70m、アスペクト ≤1.25、構成線分 ≥15本、閉合率 ≥0.9 のループを抽出する。実測：真のバブルは Ø0.368（40線分）・Ø0.600（36線分）。
2. **ラベル**：ループ中心から 0.6m 以内に `^[A-Za-z]?\d{1,2}$`（X1・Y3・4・L1 など）のテキストがあること。実測：ラベル付きループ 61個（真のバブル 50個、誤認 11個＝器具タグ T99・T6・「9」・「50」/「60」）。直径だけでは分離できない（バブル Ø0.368/0.600 と椅子 Ø0.55 が重なる）。
3. **共線性**：同じ y（±0.1m）または同じ x（±0.1m）にラベル付きループが **3個以上** 並び、隣接間隔が 2–12m であること。実測：大天 X行 5個＠4.80m、Y列 3個＠11.40/8.00m、江南 5個＠6.08/6.08/6.09/2.00m。誤認 11個はすべて 2個以下の並びで落ちる。
4. **線**：バブルの並びから 0.65m 以内に、長さ ≥5m の実線ラン（単一線分または共線チェーン、実線率 ≥0.95）が通り、最も外側のバブルまで届くこと。**線が面の内部にあることは要求しない**（通り芯は面外にある）。壁接触も要求しない。
5. 上記 3＋4 を満たす誤認は **5図面で 0件**。

### 訂正 — タスクで案として出した円テストは使えない

クラスタの `arcShare≥0.85 かつ short≤300mm` というテストは全図面で **0件**。理由：(1) 純粋な円は furndetect のフィルタ（`arcShare>=0.85 && inner==0` を落とす）でクラスタから除外されている、(2) 実際のバブルは Ø368–600mm で short 辺 368–600mm で 300mm 閾値に入らない。**円は `segs` から直接、短い線分の連結ループとして検出すること**（上のルール1）。

### 確かめ方

- 上記ルールを 5図面の dump に適用し、期待値と突き合わせる。大天：通り芯 10本・バブル 40個（X 25＋Y 15）。江南：通り芯 2本・バブル 10個。ジェイテクト・日本モウルド・三井屋：0本。
- 村中さんの紫線の区画正解と照合し、検出した通り芯を除いても区画数が変わらないこと（通り芯は区画を割らない）。
- 偽陽性リスク：器具タグ付きの円が 3個以上並ぶ図面では誤認しうる（現データでは 0件）。バブルが 3個未満の短い建物は検出できない。
